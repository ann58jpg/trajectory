# Решения, принятые по ходу работы

1. **Next.js 16.4 вместо 15.** Все версии Next 15 и ранние 16 в npm audit помечены критической уязвимостью; 16.4.2 — без уязвимостей (`npm audit --omit=dev`: 0). Параметры маршрутов асинхронные (`params: Promise<…>`).
2. **Drizzle + better-sqlite3 вместо Prisma.** Prisma скачивает движки с внешнего хоста, недоступного в песочнице; drizzle работает офлайн. Справочники хранятся как JSON-документы (`id`, `data`) и валидируются zod при seed и при чтении. Миграция — `drizzle/0000_init.sql`.
3. **Справочники вшиты в сборку как фолбэк.** Если `npm run setup` не запускали или БД повреждена, приложение читает `data/*.json` через статический импорт. Это и требование «работать всегда», и защита от трассировки всей файловой системы в сборке.
4. **shadcn/ui без CLI.** Компоненты (`components/ui/*`) написаны вручную в стиле shadcn: Radix + cva + tailwind-merge. CLI требует сети и интерактива.
5. **Шрифты системные.** `next/font/google` скачивает шрифты при сборке, это ломает офлайн-сборку. Используется системный стек (Inter, если установлен).
6. **Ползунок — три опорные точки.** t=0 «Интересы», t=0.5 — базовая формула модели из ТЗ (0.30/0.25/0.20/0.15/0.10), t=1 «Деньги», интерполяция кусочно-линейная. Так середина ползунка совпадает с исходной моделью. Ползунок управляет обеими вкладками: «Интересы» показывает специальности → профессии, «Деньги» — профессии с порогом метча ≥ 0.25 при любом t и подсказку «сдвинуть на “Деньги”», если t < 0.5. «Сравнение» всегда показывает крайние положения.
7. **«Не готов переезжать» + онлайн.** Вузы других городов исключаются жёстким фильтром. Во вкладке «Интересы» показываются только вузы города и онлайн-программы вузов своего региона (например, «Росдистант» ТГУ для Самарской области). Онлайн-программы вузов других регионов не выводятся там как вузы — на них ведёт ссылка «ещё N онлайн-программ» на странице профессии. Так выполняется критерий «для Артёма нет ни одного вуза вне региона».
8. **Два вида карточек «Если готов изменить…».** (а) Профессия не прошла фильтры или ЕГЭ, но даёт ≥ +25% к лучшему варианту из «Интересов»; (б) интересная профессия уже доступна, но переезд в крупный город даёт ≥ +25% к её зарплате. Второй вид нужен для сценария Артёма: «переезд в Самару → +37%». Изменения взвешены по «стоимости» (переезд в регионе 1, к соседям 1.5, по России 2.5, ЕГЭ 1.5 за предмет, платное 2…), сортировка — выигрыш / стоимость. Не больше двух карточек с одинаковым набором изменений. Если изменений с выигрышем нет (Камила, Илья), показывается честное пустое состояние.
9. **Где считается зарплата.** В городе проживания (коэффициент региона × коэффициент города). Если человек готов переехать — в лучшем доступном городе, где есть профильная отрасль, с поправкой на стоимость жизни. Удалённая работа сокращает разрыв с уровнем крупного города на 55% (`ENGINE.remoteConvergence`), а не до конца: иначе джун из малого города получал бы «московскую» зарплату.
10. **Шанс поступления.** Сумма трёх предметов пользователя против диапазона проходного: выше верхней границы — «высокий», выше середины — «средний», не ниже «мин − 5» — «низкий», иначе «рискованно». Творческий экзамен (ДВИ) оценивается средним баллом по остальным предметам. Для СПО сравнивается средний балл аттестата (в данных он хранится ×100). Для программ без бюджета шанс считается по минимальным баллам.
11. **Скоринг программ.** 0.30·шанс + 0.25·топ-5 критериев (вес 5…1 по рангу) + 0.15·стоимость + 0.15·логистика + 0.15·совместимость с горизонтом денег. Колледж штрафуется, если деньги не нужны срочно. Отъезд в вуз сильно слабее уровня абитуриента (балл на 35+ выше верхней границы проходного) — небольшой штраф.
12. **ВУЦ доступен только очникам.** При обязательном ВУЦ отсекаются заочные и онлайн-программы даже у вузов с ВУЦ.
13. **Ссылки.** Из песочницы недоступны сайты вузов, поэтому пути, которые не удалось проверить, заменены корнем официального домена (уверенные адреса, например `ba.hse.ru`, `pk.mipt.ru`, `abit.itmo.ru`, оставлены). Вузопедия и «Поступи онлайн» открываются поиском Яндекса по сайту: точные адреса страниц вузов на этих сервисах проверить не удалось. Есть скрипт `npm run check-links`.
14. **Таймауты ИИ.** 20 с для разбора текста и объяснений, 45 с для веб-поиска мероприятий: поиск с несколькими запросами объективно дольше. Повтор — один раз (встроенные ретраи SDK выключены), затем фолбэк.
15. **Модель и инструмент.** `ANTHROPIC_MODEL` по умолчанию `claude-sonnet-5-5` (как в ТЗ), web search — `web_search_20260209` (актуальная версия с динамической фильтрацией для этой модели). Включён серверный фолбэк при отказе модели: `fallbacks: "default"` (на неподдерживаемых моделях запрос просто выполняется без фолбэка).
16. **Структурированный ответ ИИ.** Модель отвечает текстом с JSON, мы вырезаем JSON и проверяем zod. Встроенные structured outputs не используются: вместе с web search и цитатами они ограничены, а единый путь проще для провайдеров-заглушек.
17. **Персональные данные.** Анкета живёт в `localStorage` (все обращения в try/catch). Сервер её не сохраняет; кэшируется только ответ ИИ по хэшу текста. Пол спрашивается только для ВУЦ и используется для согласования рода в портрете («готова»).
18. **«Скачать PDF».** Печать браузера с print-стилями («Сохранить как PDF»), без серверной генерации — меньше зависимостей.
19. **Вне ТЗ добавлены** хобби «Дроны» и «Космос», критерий «Олимпиады вуза», колледжи СПО и филиалы в малых городах (Сызрань): иначе сценарий «нужен доход с 1–2 курса, без переезда» был бы пустым.
20. **SQLite на Vercel.** База собирается при деплое (`vercel-build`), едет вместе с функцией и при первом запросе копируется в `/tmp`, чтобы работал кэш. Внешняя БД (Turso, Postgres) не нужна: справочники читаются, а не пишутся, а кэш допустимо держать на инстанс. Проверено `vercel build`: база и `better_sqlite3.node` попадают во все функции, seed выполняется на шаге сборки.

## Правки v2

**Сохранили то, что работало.** Движок (факторы, веса и /admin/weights), SQLite и деплой на Vercel, «Мой план», страницы профессии, направления и вуза. Меняли только то, что указано в правках.

1. **Тексты.** Все тексты интерфейса лежат в `lib/copy.ts`, тексты служебных страниц — в `app/admin/copy.ts`. Тест `tests/unit/copy.test.ts` ищет запрещённые слова в коде интерфейса, промптах и строках данных. Официальные названия направлений из перечня Минобрнауки («Строительство уникальных зданий…») из проверки исключены: переписывать их нельзя. Слово «Траектория» осталось только как название-логотип (`BRAND`).
2. **ЕГЭ.** Русский всегда в наборе, и без его балла шанс не считается. Базовую математику показываем отдельно и честно предупреждаем, что с ней на бюджет почти никуда. Готовность к доп. экзаменам (ДВИ) — отдельный вопрос. Программы, где нужен ДВИ, к которому человек не готов, уходят в «Если готов изменить».
3–4. **Каталог.**
   - Перечень направлений собран как на tabiturient.ru/np: 281 направление в 56 группах. Сам сайт из песочницы недоступен (сетевые правила), поэтому описания составили мы и пометили «описание составлено автоматически».
   - `npm run import:tabiturient` заберёт описания, дни открытых дверей и проходные баллы там, где есть интернет. Скрипт делает паузы и записывает источник в файл. `gen-catalog.py` подставит импортированные описания вместо наших.
   - Вузов и колледжей 240, регионов с вузами 76, есть все 8 округов. Региональные вузы ранжируются наравне с московскими: в формуле нет бонуса за столицу.
   - Если домен вуза не удалось проверить, в ссылке стоит поиск Яндекса по названию.
   - **Бюджетные места и проходные для новых программ — `null`, а не выдуманные числа.** `null` в `budgetPlaces` значит «бюджет в вузе есть, число не проверено». Интерфейс показывает рамку DataGap.
5. **Игра.**
   - 164 карточки из задач профессий (`scripts/gen-task-cards.py`), по 2–3 на каждую из 56 групп. Группы сведены в 11 сфер.
   - Первые 5 раундов показывают все сферы. Дальше раунды чередуют 2–3 любимые сферы, и каждый третий раунд добавляет «разведочную» карточку.
   - Раунды детерминированы: после перезагрузки страницы карточки те же.
   - Старые пары задач больше не задаются, поле `taskPairs` оставлено для совместимости сохранённых ответов.
6. **Формат работы.** 15 вариантов. Те же метки стоят у всех 210 профессий. В совпадении это 15%, игра — 25%.
7. **Результаты.**
   - Вместо вкладок один список: топ‑5 направлений, профессия показывается один раз, не больше двух направлений из одной группы, остальные — в «Показать похожие».
   - Тест покрытия: для каждой из 56 групп есть анкета, при которой её направление попадает в топ‑10.
   - Госуправление не появлялось, потому что у РАНХиГС не было программы 38.03.04. Её добавили, а у профессии направления теперь упорядочены так, что первым идёт то, где она главная.
8. **DataGap.** Правило одно для всего приложения: подтверждено → цифра с источником, оценка → пометка «оценка», данных нет → рамка. Режим презентации хранится в браузере (`/admin`).
9. **Аналитика.**
   - События идут в Метрику и в `/api/track`. Внешняя БД выбирается по схеме `DATABASE_URL`: `postgres://` — Neon, `libsql://` — Turso. Без БД события пишутся в консоль и в память процесса.
   - В отзыве собираем только оценку 1–5, без текста, чтобы не получить личные данные.
   - `track()` отправляет события через `fetch` с `keepalive`, а не `sendBeacon`: так запрос видно в тестах, и он всё так же доходит при уходе со страницы.
10. **«Если готов изменить».** Предлагаем только смежное: та же группа, что у подходящих направлений, или ЕГЭ отличается не больше чем на один предмет, или общие интересы (теги, задачи из игры). Не больше двух изменений и не больше 5 вариантов, по пользе (совпадение, выигрыш в деньгах, цена изменений). Если близких вариантов нет, честно пишем, что их нет.
11. **Переключатель.**
    - Веса режимов — те же якоря `interests`/`money`, страница весов работает.
    - Порог совпадения в режиме «по доходу» поднят с 0,25 до 0,4: иначе туда попадали профессии, не связанные с интересами (медсестра в Салехарде у будущей актрисы).
    - Доход нормируется от минимума до максимума по всем 210 профессиям, чтобы разница была заметна.
12. **Проходные баллы.**
    - Страницы вузов и агрегаторов из песочницы не открываются, поэтому брали только числа из выдачи поиска, где явно указаны год, программа и вид мест и источники не противоречат друг другу.
    - Итог: подтверждённых баллов 2026 года — 0 (по каждой найденной программе источники расходятся или это промежуточные цифры). Баллов 2025 года — 5 по 4 программам. Отклонённые числа с причиной лежат в `data/pass_scores.json`.
    - Старые оценочные диапазоны оставлены с пометкой «оценка», в режиме презентации они скрыты.
13. **Отказ в тексте мечты.** Фразы «не хочу», «не моё», «не люблю» превращаются в отказ от главного тега ключевого слова: «медицина не моё» снижает совпадение с врачом, но не с ветеринаром.

**Мероприятия.** Даты есть только у 5 событий, подтверждённых поиском по официальным сайтам вузов (`data/events_verified.json`). У остальных — «когда обычно бывает» и ссылка на сайт вуза, а в блоке «Куда сходить в ближайший месяц» — честное «событий с датой нет».

## Данные tabiturient.ru и официальных сайтов (ноябрь 2026)

- **Что есть на tabiturient.ru.** Список всех 809 вузов и филиалов с регионом и пометкой «филиал» (`ajax/ajvuz1.php`). Страница каждого вуза (официальный сайт, бюджетные места). Страницы 292 направлений бакалавриата и специалитета: статистика по России, реальные наборы ЕГЭ и все программы всех вузов с проходными баллами. Дни открытых дверей по 84 регионам со ссылкой на анонс вуза.
- **Чего там нет.**
  - Текстовых описаний направлений: заменить автоматические описания было нечем, они остались с пометкой «описание составлено автоматически». Вместо этого у направлений теперь реальные данные: бюджетные места по России, число вузов, средний проходной балл, наборы ЕГЭ.
  - Проходных баллов 2026 года: последний год на сайте — 2025.
- **Сопоставление вузов.** По полному названию, затем по короткому в том же регионе (Москва и Петербург считаются вместе с областью), затем по домену сайта и словам названия. Для нескольких вузов задано явное соответствие (`EXPLICIT` в `scripts/data_src/tabiturient.py`). Вузы, которых нет на tabiturient (Гнесинка, Щукинское, Школа‑студия МХАТ и др.), остались из нашего списка.
- **Неизвестное — «нет данных», а не выдумка.**
  - У добавленных вузов общежитие, военная кафедра и цена — `null`, рейтинг у работодателей нейтральный, 0,5, с пометкой.
  - Если общежитие или военная кафедра обязательны, вуз без данных исключается с причиной «нет данных — уточни в вузе».
  - Неизвестная цена показывается рамкой DataGap. «Учёбу оплачивает работодатель» осталось только у вузов с признаком `sponsored`.
- **Город.** Для головного вуза — столица региона, для филиала — город из названия («… в г. Сызрани»), иначе столица. Это приближение: точных адресов в источнике нет.
- **Новые регионы.** Семь регионов (Тыва, Ингушетия, Карачаево‑Черкесия, Республика Алтай, ЕАО, Магаданская область, Чукотка) получили зарплатные коэффициенты как среднее по своему округу, с пометкой «оценка».
- **Наборы ЕГЭ.** Если наборы вузов согласованы (общих предметов хотя бы два), реальные наборы заменяют наши: изменилось 196 направлений.
- **Проходные баллы.**
  - По программе берём минимальный балл на бюджет (очно) среди её профилей за последний год.
  - Официальные данные вузов главнее агрегаторов: 2026 год — ВШЭ (по приказу о зачислении от 07.08.2026, минимальная сумма конкурсных баллов) и Институт естественных наук и математики УрФУ. Остальные вузы итогов 2026 в разборчивом виде не публикуют.
  - Расхождение по ВШЭ «Программная инженерия» за 2025 год (Lancman 299, tabiturient 297) решено в пользу tabiturient.
- **Скорость.** С 12,9 тысячи программ поиск перебором внутри циклов стал квадратичным (2,4 с на подбор). Индексы каталога (`lib/engine/index.ts`) вернули время к ~0,3 с.
- **«Где учиться».** Десять лучших программ плюс вузы, отмеченные в анкете, плюс до трёх вузов своего города.

## v3 — решения, принятые самостоятельно

- **Структура.** 5 разделов (Маршрут, Подбор, Вузы, Лента, Профиль): снизу на телефоне, слева на компьютере. Режим для родителей убран полностью. СПО и магистратура в верхней панели видны, но отключены с пометкой «скоро».
- **Год поступления.** 11 класс → ближайшая кампания (2027), 10 и 9 класс → 2028 (дальше календарь не строим). Год можно сменить вручную. Для 2028 даты сдвинуты на год и помечены «ожидаемая дата».
- **Календарь приёма** (`data/admission_calendar.json`). Даты 2027 года — из порядка приёма и расписания ГИА. Итоговое сочинение 2026/27 и сроки ЕГЭ 2027 официально не утверждены, поэтому `confirmed: false`.
- **Вайб вуза.**
  - 6 порядковых шкал + досуг + дух вуза (вместе 8) и 3 тега из 20; в тесте 13 вопросов.
  - Вайб показываем от 10 ответов, до этого — DataGap «Собираем вайб: N из 10».
  - Демо-вайб выключен по умолчанию. У ВШЭ ровно 9 демо-ответов: на показе 10-й реальный ответ «включает» вайб.
  - Вес вайба в подборе — 0,15, меняется в /admin/weights.
  - Одно устройство — один ответ на вуз; повтор заменяет ответ.
- **Хранилище.** Ответы о вайбе и истории выпускников лежат в таблице `docs` той же базы: `DATABASE_URL` — postgres (Neon) или libsql (Turso). Без неё — локальный SQLite `data/local-store.db` с предупреждением в консоли (на Vercel — `/tmp`, данные пропадут).
- **Страница вуза.** Порядок: шапка (совпадение по специальностям и вайбу, ★) → вайб → программы и шансы → студенческая жизнь → известные выпускники → куда приходят выпускники → события для абитуриентов. В конце сохранили блоки v2 «О вузе», «Рейтинги» и «Как добраться».
- **Студенческая жизнь.**
  - Сообщества 30 крупных вузов взяты из Wikidata (VK — P3185, Telegram — P3789), у каждого есть ссылка на источник.
  - Ежегодное событие с источником подтверждено только у МГУ (посвящение, сентябрь). У остальных честно пишем «не подтверждено» и даём ссылки на сообщества. Месяцы и даты не выдумываем.
  - Свежие посты VK — только при заданном `VK_SERVICE_TOKEN`.
- **Известные выпускники.**
  - Источник — Wikidata P69 «учился в», отбор по числу статей в Википедиях, без фото.
  - Политиков, госслужащих, дипломатов и людей, известных прежде всего политикой или уголовными делами, не показываем: блок про профессии. Это редакционное решение, его можно пересмотреть.
  - Только родившиеся с 1900 года.
  - У Самарского университета и ЮФУ в Wikidata мало записей (1 и 3).
- **Стажировки.**
  - Поиск вакансий в API hh.ru без токена приложения отвечает 403. Сделан вход по `client_credentials`; без ключей — DataGap и ссылка на поиск hh.ru.
  - Программы компаний собраны вручную. Сайты Сбера, Т-Банка, Альфы, Росатома, РЖД, Газпром нефти и Б1 из песочницы не открылись — у них `confirmed: false` и пометка «проверь ссылку».
  - Вместо Big4 — их российские преемники: ТеДо, Kept, Б1, ДРТ.
- **Лестница по курсам** одна для всех: 1 курс → 2 курс → 3–4 курс → после выпуска, на каждой ступени 2–4 проверенные ссылки.
- **Истории выпускников.** Публикуются только после модерации в /admin/stories (пароль `ADMIN_PASSWORD`). Без фамилий и контактов, согласие обязательно. Профили hh и LinkedIn не собираем.
- **«Один шаг до…»** заменил «Если готов изменить».
  - Близость — по группам ОКСО из `data/sphere_neighbors.json`, от группы лучшей профессии; плюс те же группы у топ-3 и минимум два общих тега интересов.
  - Ровно одно изменение.
  - Выгода — одно из трёх: зарплата +25% и больше, вуз выше в RAEX минимум на 10 мест, вакансий в 1,25 раза больше.
  - Дальний переезд — только ради заметно более сильного вуза.
  - У экономики сосед только математика (аналитика), поэтому экономисту не предлагаются ИВТ и творческие направления.
  - Если честных вариантов меньше трёх, показываем меньше, а не добиваем слабыми.
- **«Безопасный выбор».**
  - Показываем, если ЕГЭ — обществознание + язык (или обществознание без профильных предметов), а в ответе «почему эти предметы» стоит «проще всего», «посоветовали» или «не знаю».
  - Цифры по менеджменту и экономике: программы, проходной, зарплата-оценка, «нужно сдать профильную математику».
  - Вопрос о мечте показывает направление и один предмет, который нужно добавить, плюс напоминание .ics на 1 февраля.

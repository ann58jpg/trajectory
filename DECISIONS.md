# Решения, принятые по ходу работы

1. **Next.js 16.4 вместо 15.** Все версии Next 15 и ранние 16 в npm audit помечены критической уязвимостью; 16.4.2 — без уязвимостей (`npm audit --omit=dev`: 0). Параметры маршрутов асинхронные (`params: Promise<…>`).
2. **Drizzle + better-sqlite3 вместо Prisma.** Prisma скачивает движки с внешнего хоста, недоступного в песочнице; drizzle работает офлайн. Справочники хранятся как JSON-документы (`id`, `data`) и валидируются zod при seed и при чтении. Миграция — `drizzle/0000_init.sql`.
3. **Справочники вшиты в сборку как фолбэк.** Если `npm run setup` не запускали или БД повреждена, приложение читает `data/*.json` через статический импорт. Это и требование «работать всегда», и защита от трассировки всей файловой системы в сборке.
4. **shadcn/ui без CLI.** Компоненты (`components/ui/*`) написаны вручную в стиле shadcn: Radix + cva + tailwind-merge. CLI требует сети и интерактива.
5. **Шрифты системные.** `next/font/google` скачивает шрифты при сборке, это ломает офлайн-сборку. Используется системный стек (Inter, если установлен).
6. **Ползунок — три опорные точки.** t=0 «Интересы», t=0.5 — базовая формула модели из ТЗ (0.30/0.25/0.20/0.15/0.10), t=1 «Деньги», интерполяция кусочно-линейная. Так середина ползунка совпадает с исходной моделью. Ползунок управляет обеими вкладками: «Интересы» показывает специальности → профессии, «Деньги» — профессии с порогом метча ≥ 0.25 при любом t и подсказку «сдвинуть на “Деньги”», если t < 0.5. «Сравнение» всегда показывает крайние положения.
7. **«Не готов переезжать» + онлайн.** Вузы других городов исключаются жёстким фильтром. Во вкладке «Интересы» показываются только вузы города и онлайн-программы вузов своего региона (например, «Росдистант» ТГУ для Самарской области). Онлайн-программы вузов других регионов не выводятся там как вузы — на них ведёт ссылка «ещё N онлайн-программ» на странице профессии. Так выполняется критерий «для Артёма нет ни одного вуза вне региона».
8. **Два вида карточек «Если готов изменить…».** (а) Профессия не прошла фильтры или ЕГЭ, но даёт ≥ +25% к лучшему варианту из «Интересов»; (б) интересная профессия уже доступна, но переезд в крупный город даёт ≥ +25% к её зарплате. Второй вид нужен для сценария Артёма: «переезд в Самару → +37%». Изменения взвешены по «стоимости» (переезд в регионе 1, к соседям 1.5, по России 2.5, ЕГЭ 1.5 за предмет, платное 2…), сортировка — выигрыш / стоимость. Не больше двух карточек с одинаковым набором изменений. Если изменений с выигрышем нет (Камила, Илья), показывается честное пустое состояние.
9. **Где считается зарплата.** В городе проживания (коэффициент региона × коэффициент города). Если человек готов переехать — в лучшем доступном городе, где есть профильная отрасль, с поправкой на стоимость жизни. Удалённая работа сокращает разрыв с уровнем крупного города на 55% (`ENGINE.remoteConvergence`), а не до конца: иначе джун из малого города получал бы «московскую» зарплату.
10. **Шанс поступления.** Сумма трёх предметов пользователя против диапазона проходного: выше верхней границы — «высокий», выше середины — «средний», не ниже «мин − 5» — «низкий», иначе «рискованно». Творческий экзамен (ДВИ) оценивается средним баллом по остальным предметам. Для СПО сравнивается средний балл аттестата (в данных он хранится ×100). Для программ без бюджета шанс считается по минимальным баллам.
11. **Скоринг программ.** 0.30·шанс + 0.25·топ-5 критериев (вес 5…1 по рангу) + 0.15·стоимость + 0.15·логистика + 0.15·совместимость с горизонтом денег. Колледж штрафуется, если деньги не нужны срочно. Отъезд в вуз сильно слабее уровня абитуриента (балл на 35+ выше верхней границы проходного) — небольшой штраф.
12. **ВУЦ доступен только очникам.** При обязательном ВУЦ отсекаются заочные и онлайн-программы даже у вузов с ВУЦ.
13. **Ссылки.** Из песочницы недоступны сайты вузов, поэтому пути, которые не удалось проверить, заменены корнем официального домена (уверенные адреса, например `ba.hse.ru`, `pk.mipt.ru`, `abit.itmo.ru`, оставлены). Вузопедия и «Поступи онлайн» открываются поиском Яндекса по сайту: точные адреса страниц вузов на этих сервисах проверить не удалось. Есть скрипт `npm run check-links`.
14. **Таймауты ИИ.** 20 с для разбора текста и объяснений, 45 с для веб-поиска мероприятий: поиск с несколькими запросами объективно дольше. Повтор — один раз (встроенные ретраи SDK выключены), затем фолбэк.
15. **Модель и инструмент.** `ANTHROPIC_MODEL` по умолчанию `claude-sonnet-5-5` (как в ТЗ), web search — `web_search_20260209` (актуальная версия с динамической фильтрацией для этой модели). Включён серверный фолбэк при отказе модели: `fallbacks: "default"` (на неподдерживаемых моделях запрос просто выполняется без фолбэка).
16. **Структурированный ответ ИИ.** Модель отвечает текстом с JSON, мы вырезаем JSON и проверяем zod. Встроенные structured outputs не используются: вместе с web search и цитатами они ограничены, а единый путь проще для провайдеров-заглушек.
17. **Персональные данные.** Анкета живёт в `localStorage` (все обращения в try/catch). Сервер её не сохраняет; кэшируется только ответ ИИ по хэшу текста. Пол спрашивается только для ВУЦ и используется для согласования рода в портрете («готова»).
18. **«Скачать PDF».** Печать браузера с print-стилями («Сохранить как PDF»), без серверной генерации — меньше зависимостей.
19. **Вне ТЗ добавлены** хобби «Дроны» и «Космос», критерий «Олимпиады вуза», колледжи СПО и филиалы в малых городах (Сызрань): иначе сценарий «нужен доход с 1–2 курса, без переезда» был бы пустым.
20. **SQLite на Vercel.** База собирается при деплое (`vercel-build`), едет вместе с функцией и при первом запросе копируется в `/tmp`, чтобы работал кэш. Внешняя БД (Turso, Postgres) не нужна: справочники читаются, а не пишутся, а кэш допустимо держать на инстанс. Проверено `vercel build`: база и `better_sqlite3.node` попадают во все функции, seed выполняется на шаге сборки.
